# Engineering notes

User-facing installation and usage instructions live in the [README](../README.md). Run the commands below from the repository root.

A quiet Electron Markdown **source** editor. Start typing immediately, recover unnamed thoughts, open existing files, search within the source, jump between chapters, deliberately open links, autosave after a typing pause and safely handle external/agent changes. No tabs, file tree or preview.

## Search and links

**Ctrl+F**, or **Menü → Im Dokument suchen**, opens a compact, case-insensitive literal search. Matches are highlighted with a current/total count. **Enter / Shift+Enter** and the arrow buttons wrap through matches. Empty queries and no matches have explicit states; editing recalculates matches. Autosave keeps query typing in the search input, and external reloads retain the open query, input caret and focused search control. **Escape** or the close button returns focus to the editor. There is no replace function.

**Ctrl+click** a Markdown link label or destination to open HTTP/HTTPS links in the system browser. Ordinary clicks only position the cursor. Inline links, autolinks and reference links are supported; code and image syntax are not browser-launch actions. Inline/reference destinations decode Markdown escapes and entities; autolinks retain their literal destination. Relative files, anchors and other URL schemes are refused rather than routed through the privileged app window. The gesture is also explained in the menu.

## Chapter index

Hold **Alt** briefly to show an H1/H2 index of the document (H2 indented); release Alt to dismiss it without jumping. **Arrow up/down** and **Enter**, or a click, scroll to a heading; the writing cursor and selection stay where they were and focus returns to the editor. After a jump or **Escape** the index stays closed until Alt is pressed anew. **Menü → Kapitelindex** opens the same index without holding; Escape, a choice or a click outside closes it. Frontmatter and code blocks never produce chapters, and a document without headings says so. Other Alt combinations and AltGr pass through untouched; switching windows closes the index. No global shortcut is registered.

## Run locally

On the initial Windows target, install Node.js 22.12+ (validated with Node 24), then:

```sh
npm ci
npm start
```

Electron downloads its runtime during installation/first use; allow its installation step if your npm policy requires approval. `npm start` builds the app and opens its desktop window. No development web server is needed. A Windows x64 installer is available; other platforms are not packaged yet.

The app/package and verification skill are now named **md0** and **verify-md0**. Existing default `zen-markdown` profiles are reused when no md0 profile exists, so the rename does not hide drafts, conflict backups or recent files. No user profile is moved or deleted. Explicit `--user-data-dir` overrides remain untouched. In a host that exports `ELECTRON_RUN_AS_NODE=1`, remove that variable from the launching shell before desktop runs (`Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue` in PowerShell).

Startup opens a focused empty editor, or the most recently edited unsaved **unnamed draft**. No picker is needed. When starting with a file path, an existing draft or recovery warning remains visible in its own window alongside that file. Drafts show `Lokal gesichert` once protected locally; **Ctrl+S** opens a Markdown save dialog. Cancel keeps the draft; existing targets are refused. Saving successfully retires that draft's recovery record, so the next startup is blank unless another unsaved draft remains. **Neues Dokument / Ctrl+N** parks the current unnamed draft and opens a fresh one; from a named document it opens a separate window. Opening another file retains existing work in its window; only an empty unnamed editor is reused. There is no draft library/navigation UI.

Existing files autosave **1.5 seconds after the last edit**: a short phrase can be finished without a write per keystroke. `Ungespeichert` stays visible until saving completes; there are no per-save success popups. Use the upper-left icon to open a file and save it immediately, or **Ctrl+O / Ctrl+S**. The icon is reachable with Tab and has visible keyboard focus. Escape closes its menu. Light/dark follows the OS. Local iA Writer Mono is provisional; its license is in `assets/fonts/LICENSE.md`.

## Install on Windows

Run `npm run dist:win` to build `dist/md0-Setup-0.1.0.exe` (the filename follows the package version). Run the installer to install for the current user under `%LOCALAPPDATA%\Programs\md0`, without administrator rights. It adds a Start menu shortcut and registers `.md`, `.markdown`, and `.mdown` file associations. To make md0 your default, open **Settings → Apps → Default apps**, search for `.md`, and select **md0**; repeat for the other extensions if desired. Windows may require this explicit user confirmation. The installer is currently unsigned and may show a Windows security warning. Uninstall through **Settings → Apps → Installed apps**.

## Open from Windows without an installer

Build once, then invoke Electron directly (PowerShell):

```powershell
npm run build
& .\node_modules\.bin\electron.cmd . "C:\Notes\Grüße mit Leerzeichen.md"
```

Run the same command again with another path while the app is running: it reaches the same app and opens another window. Reopening a file focuses its existing window (restoring it if minimized). Paths are resolved through the filesystem, including symbolic links; Windows canonical paths are compared case-insensitively. Distinct hard-link paths are not deduplicated and should not be used to edit the same file concurrently. Multiple path arguments are supported. A development `--user-data-dir="C:\Temp\md0-test-profile"` argument before the file selects an isolated profile; use the same profile for subsequent invocations. Use the installer above for persistent Windows file associations.

Drop a local Markdown file onto the editor, use **Ctrl+O**, or choose a path under **Zuletzt verwendet** in the menu. These use the same open routing. Supported extensions are `.md`, `.markdown`, `.mdown`, and `.txt`. The first file in a multi-file drop is used. A nonempty unnamed draft or named document stays in its own window. A failed open shows an error without creating a damaged editor. Up to ten recent canonical paths (no document content) are stored locally in `userData/recent-files.json`; missing entries remain available for a later retry. Successful draft-to-file saves also appear there.

## Safety and scope

- Disk access lives in `src/main/`; a sandboxed, context-isolated renderer receives only named document operations through `src/preload.ts`. It cannot choose arbitrary write paths or access Node. Navigation, new windows, permissions and network access are blocked.
- Each window owns one document session. Main-process operations, including dialogs, run on one application queue. During open/save/close, that window's editing is frozen. Opening another file never discards existing edits. Closing a dirty named document still requires explicit discard confirmation; cancel and save first to retain edits.
- External changes are checked every second through the same main-process queue as open/save/edit. This polling monitor survives replacement/rename and missed filesystem notifications. A refresh briefly locks editing while reading, so no edit can acknowledge a stale disk base. Clean files reload automatically; selection is mapped through the changed range, scroll is retained where possible and undo history starts fresh (old raw-source snapshots must not resurrect pre-update content). A short update notice disappears after five seconds. Autosave uses the same queued, conflict-protected save as Ctrl+S; the timer is suspended during commands and canceled on a successful document switch. A canceled switch/close keeps pending work. A close requested during another command is handled afterward.
- A conflict or error pauses autosave, even if typing continues. Local text remains editable. After fixing an access problem, retry with **Ctrl+S** or **Speichern** in the menu; no automatic retry loop runs. Missing/changed originals still require conflict resolution rather than being recreated/overwritten. Unnamed documents never trigger an automatic save dialog; they use separate local draft protection instead. A restored conflict backup is not autosaved until the user edits it or explicitly saves.
- When local work and disk diverge, the text stays put and the visible conflict actions are **Dateiversion laden** and **Meine Version als Kopie speichern**. Deletion/inaccessibility also blocks saving; the app never recreates a missing original automatically. The load action reads the latest disk version, not a cached conflict snapshot. Refreshes are skipped while a command runs; switching files naturally retargets the next poll and unloading the renderer cancels the monitor.
- Before loading the disk version, the local raw UTF-8 text is written, synced and atomically published as an immutable backup under Electron's `userData/conflict-recovery/`. Backup failure aborts loading without discarding text. After restarting, choose **Lokale Sicherung wiederherstellen** directly from the menu to restore the most recent backup, even when its original is missing or invalid UTF-8. Alternatively, open a file first to recover its latest backup specifically. Recovery puts the local text in the editor without changing disk. If its file is already open in another window, that window is focused and recovery in the unnamed window is refused with guidance to restore there; no second editing session is created. An absent/unreadable original remains in conflict; save the recovered text as a copy at a different location. Dirty text requires discard confirmation before recovery. Backups are local, unencrypted, retained on disk and are not a note library. File sync protects completed writes across normal restarts, not an absolute hardware/power-loss guarantee.
- Copy saving leaves the original document/conflict open. Cancel changes nothing. A synced sibling staging file is published with a no-replace hard link: existing targets are refused even if an OS picker approved replacement. The original pathname is independently rejected (including Windows case aliases), even if the original has been deleted. Choose a fresh name. Filesystems without hard-link support produce a visible error, not an unsafe fallback.
- Save compares the loaded bytes and file identity/timestamps, writes and syncs a sibling temporary file, checks again, then replaces the original. It checks the written bytes afterward too. Failed staging never truncates the original. **This is not an OS-level compare-and-swap:** an uncooperative writer can still race the final check/rename. File watchers alone would not solve that. This app refuses detected conflicts; it does not promise arbitrary concurrent-writer exclusion.
- Files must be valid UTF-8 (with or without BOM); other encodings fail visibly instead of being silently rewritten. Existing mixed LF/CRLF/CR endings, frontmatter and whitespace remain untouched outside actual edits. Newly inserted line breaks use the file's first existing line ending (LF when none exists).
- Unnamed drafts are separate UUID records under Electron's `userData/drafts/`, unencrypted and local. Every edit acknowledged as `Lokal gesichert` has been written, file-synced and atomically published through the same serial command queue; there is no periodic backup interval. Normal close waits for pending edits and protection. Abrupt exit may lose renderer text not yet delivered/acknowledged, or an in-flight write; the previous complete record survives atomic publication. File sync is not an absolute hardware/power-loss guarantee. Draft protection errors stay visible and prevent switching/closing until protection succeeds or the text is saved as a file. Each draft has its own identity; saving one removes only its record. Older parked drafts remain recoverable on subsequent startups after the latest is saved. Draft JSON errors are reported without deleting the original record; valid remaining drafts are still considered for recovery. Interrupted `.tmp` files are not loaded. Each new draft starts a fresh editor undo history, even when the previous draft was also empty. General recovery of unsaved **named** edits is not provided: those still require saving or explicit discard, except for the explicit conflict-load backup. Very large-file tuning belongs to later work. Atomic replacement preserves basic file mode, not all filesystem-specific metadata/ACLs/hard-link relationships.

## Editor choice

The production editor is a fresh **CodeMirror 6** integration, not the prototype textarea/paint overlay. It provides visible Markdown syntax, source-positioned transactions, undo history, selection mapping, viewport access and a Markdown parser. Search uses CodeMirror's search state with a search-only custom panel; link activation resolves the Markdown syntax tree and validates URLs again in the main process. The chapter index reads H1/H2 nodes from the same syntax tree and scrolls with CodeMirror effects, so the selection is never touched. External updates map selections and retain scroll. No preview or cursor-dependent syntax hiding is installed. The centered page, 70px outer top/bottom margins and restrained typography take variant A as the visual reference.

CodeMirror normalizes logical line positions. The renderer applies its change ranges to the original raw source rather than serializing the entire normalized document; that preserves unrelated line endings and BOM. History-aligned inverse effects also retain the raw source, so undo/redo restores actual separators rather than normalized LF text, including grouped edits. Opening a document and accepting an external replacement start fresh editor/history; external replacements map the existing selection and restore focus/scroll.

## Checks

```sh
npm run typecheck
npm run test:unit -- tests/document.test.ts
npm run test:e2e
npm test
```

The agreed seams are the document API against real temporary files and the Electron user journey. Vitest covers explicit save, byte fidelity, external conflicts, disk/read-only write failures, retained errors and canceled document switches at the session API. Playwright launches real Electron and tests menu opening, source editing, save, mixed endings, undo/redo byte fidelity (including grouped deletions), conflicts, retained work when opening another window and canceled close. The external-change tests additionally cover atomic replacement, clean reload, conflict actions, copy cancellation/failures, backup failure and recovery after restarting with the same local storage. The Electron test exercises both conflict actions and menu recovery across a real app restart. `tests/e2e/autosave.spec.ts` controls renderer time against real temporary files: debounce/coalescing, exact bytes, an external write after the last poll but before autosave, read-only/access errors, explicit retry, canceled close and independent autosave in simultaneous windows. A secondary document-API test queues a switch while a disk save is outstanding; the UI tests separately verify timer cancellation. Every Electron test owns an isolated profile. `windows.spec.ts` launches a second OS process against the same profile, checks duplicate-path focus (including Windows case aliases), retained edits and new-document windows. `recent.spec.ts` checks menu opening and persistent recent entries including a temporarily missing file; `drop.spec.ts` sends Chromium native file drag events with real OS-backed files through the actual editor drop handler, not a document helper. Draft tests restart the document lifecycle and real Electron with the same temporary storage to verify immediate focus, local recovery, independent drafts, save cancellation/refusal/failure, retirement after conversion, named autosave afterward and visible local backup failures. The isolated verification helper's `drafts` journey records typing–restart–save–blank restart. The document journeys substitute native OS picker/confirmation dialogs; file operations and editor/IPC are real. Link tests additionally intercept the external-browser boundary as described below. Conflict/recovery screenshots are captured at `test-results/conflict-actions.png` and `test-results/conflict-recovery.png`. The read-only replacement test targets Windows explicitly.

`tests/e2e/search.spec.ts` exercises shortcut/menu search, both navigation directions, empty/no-match/literal states, live edits, closing/focus and unchanged BOM/mixed-ending bytes. `links.spec.ts` drives real ordinary/Ctrl clicks, reference/autolink destinations, Markdown escapes/entities and scheme refusal. Only `shell.openExternal` is intercepted for these link tests, so no website launches as a side effect. The main-process caller/frame check and HTTP/HTTPS allowlist remain production code.

`chapters.spec.ts` drives the real overlay through held/repeated/released Alt (renderer time paused), menu entry, keyboard and mouse jumps with an unchanged selection, other Alt combinations and a real window focus change.

Run `node .agents/skills/verify-md0/scripts/verify.mjs search` or `chapters` after building for isolated search/link evidence; the other journeys and feature map live in `.agents/skills/verify-md0/SKILL.md`.

E2E captures light/dark screenshots under ignored `test-results/`. Automated screenshots do not constitute human visual acceptance of the font or typing feel. Native dialog appearance, actual browser appearance and OS-specific interaction should also be checked manually on the target machine.
